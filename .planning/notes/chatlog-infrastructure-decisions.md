# Chatlog 基础设施取舍

## 原则

Chatlog 是底层数据与原生微信能力来源，不是最终产品界面。只提取能直接支撑数据连接、线索判断和客户触达的代码；不保留通用后台结构。

## 直接保留

| 能力 | 商业价值 | 处理方式 |
|---|---|---|
| 微信账号与数据目录发现 | 降低首次使用门槛 | 内嵌到桌面程序的数据连接流程 |
| macOS Frida 取钥与逐库验证 | 获得真实聊天数据 | 保留单一路径并锁定版本与 dylib 哈希 |
| 解密、WAL 与增量更新 | 保持线索数据新鲜 | 后台任务，界面只显示进度和失败步骤 |
| 联系人、会话、历史消息读取 | 构建客户池与证据 | 作为内部本地服务，不暴露通用 API 页面 |
| 历史账号切换 | 支持业务号迁移与复盘 | 明确账号绑定，禁止多账号发送歧义 |
| 文本与图片原生发信 | 完成客户触达 | 提取为生产发送适配器并重做验证 |
| 串行 job/command/release 生命周期 | 防止共享 native 状态竞争 | 作为单一发送队列核心 |

## 改造成商业功能

| Chatlog 能力 | 新 Agent 能力 |
|---|---|
| 仪表盘 | 高意向、待激活、近期线索和触达结果仪表盘 |
| 联系人/最近会话 | 可排序的线索客户池 |
| 消息检索 | 需求、价格、时间、地点、联系方式和阻碍提取 |
| 实验性语义能力 | DeepSeek 结构化意向判断与个性化激活文案 |
| Excel 导出能力 | 客户激活表和触达结果表 |
| 发信调试 | 受控生产发送队列与发送状态中心 |

## 删除

- Web 控制台和通用导航。
- 群聊大盘、群聊对比、群成员排行。
- 朋友圈、收藏和媒体浏览器。
- 裸数据库、SQL、表浏览和 wx-cli 页面。
- 时间知识图谱、通用 RAG 和面向技术用户的模型实验面板。
- Hermes/QQ 推送和非本产品的外部桥接。
- Frida Hook 调试参数、偏移和原生日志的用户界面。

## 可复用发信源码

- `internal/wechat/send/model.go`：请求模型与严格校验。
- `runner_darwin.go`：环境检查、进程选择和脚本运行。
- `assets/native_send_once.py`：文本 protobuf、任务和清理生命周期。
- `assets/native_send_image_once.py`：图片暂存、上传、protobuf 和受控重启。
- `assets/native/single_send_agent.js`：文本任务 Hook、Req2Buf、AutoBuffer 和 Ack。
- `assets/native/image_send_agent.js`：图片上传回调、任务 Hook 和生命周期。
- `internal/chatlog/http/send_debug.go`：只提取串行 job/command/release 语义，不复制 HTTP 调试 UI。

## 强制边界

- 当前原生发送只实际支持文本和图片。
- 视频与任意文件必须新增独立适配器，不得把图片消息改类型后复用。
- 不支持的类型必须明确拒绝；不使用系统自动化或外部桥接作为替代路径。
- 所有原生任务必须有确定的 Ack 和清理终点。
