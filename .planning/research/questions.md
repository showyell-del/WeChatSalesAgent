# 技术 Spike：视频与文件原生发信

## 目标

在 macOS Apple Silicon、微信 `4.1.11.54` 和精确 dylib 哈希下，为视频与任意文件建立可重复、可验证、可清理的原生发送路径，使其达到与文本/图片相同的产品契约。

## 必须回答的问题

### 视频

1. 视频上传入口、wrapper、上下文对象和完成回调的精确偏移是什么？
2. 视频任务使用什么消息类型、protobuf 字段、缩略图和媒体元数据？
3. CDN URL、AES Key、MD5、时长、尺寸和大小如何映射到最终消息对象？
4. Req2Buf 是否复用当前 serializer，还是需要独立对象与 AutoBuffer 写入路径？
5. 哪一个响应点是真实 Ack，何时可以释放 native generation 和暂存文件？

### 任意文件

1. 文件走 AppMsg、独立上传任务还是其他 MMStartTask 类型？
2. 文件名、扩展名、大小、MD5、CDN/AES 元数据和接收方如何编码？
3. 大文件的进度、超时、取消和上传完成状态如何观测？
4. 文件名与路径的 UTF-8 长度、微信容器权限和沙箱边界是什么？
5. 接收方下载并打开后，文件名、大小和内容是否逐项一致？

## 研究顺序

1. 捕获微信手工发送一个最小视频和一个小文件的真实任务与回调。
2. 建立机器可读 profile，记录模块哈希、偏移、对象布局和消息常量。
3. 只读 Hook 验证入口、serializer 和 Ack，不发送 synthetic 消息。
4. 实现单目标单消息原型，先发给 `filehelper`。
5. 验证私聊目标、重复发送、取消、超时、失败和清理。
6. 接入统一串行会话所有者，再做批量测试。

## 每种类型的放行门槛

- 精确版本与 dylib 哈希预检通过。
- 发送前参数和文件内容校验通过。
- 接收端真实收到且内容、文件名、大小或视频元数据一致。
- 任务获得可识别 Ack，失败不会误报成功。
- 取消后不再继续上传或发送。
- 连续 100 次串行发送无错发、崩溃、持续高 CPU 或残留 helper。
- 任务结束后 Frida Script、Session、DeviceManager 和暂存文件全部清理。
- 微信仍可正常收发消息并保持目标账号登录。

## 失败即停止的条件

- 无法区分真实 Ack 与日志观测点。
- 需要依赖未验证静态地址、猜测对象布局或全局进程清理。
- 只能通过剪贴板、键鼠模拟、系统分享或 Hermes 外部桥接发送。
- 微信版本变化导致 profile 不匹配。

## 预期产物

- `video` 和 `file` 两个独立发送适配器及机器可读 profile。
- 单类型复现实验记录、失败记录和验证矩阵。
- 与统一发送队列集成的明确接口契约。
- 是否允许进入首版 UI 的 PASS/BLOCK 结论。
